# Agent-native 工具接口扩层观察

## 问题

`Agent-native 工具接口` 是否会从 coding、知识库和浏览器，继续扩展到视频、设计、演示和内容生产？

## 当前范围

这不是要判断“AI 能不能生成内容”，而是要判断：哪些创意工具开始提供 Agent 易于生成、检查、回放、修改和渲染的工作接口。

更具体地说，后续应重点看四类信号：

1. 产物是否结构化
   - 例如 HTML/CSS/JS、组件树、场景描述、时间轴、节点图，而不是只输出位图或一次性结果。
2. 是否可检查和回放
   - Agent 是否能 preview、lint、diff、re-render、继续编辑，而不是只能重新生成一遍。
3. 是否能带着上下文协作
   - 是否支持 skills、外部资料、团队上下文、设计系统、本地代码或真实数据。
4. 是否能进入真实工作流
   - 是否能接浏览器、代码库、设计系统、发布系统、内容生产管线，而不是停在 demo。

## 当前样本

- `HyperFrames`
  - 代表“代码化视频生成”，说明视频工具开始提供 Agent 更容易操作的结构化介质。
- `Figma Make / Figma agent`
  - 代表“设计和原型工作流的循环生成与上下文协作”，说明设计工具在向 agent workspace 靠拢。
- `v0 / AI app builder`
  - 代表“从 prompt 到可编辑产物，再到代码和部署”的闭环。
- `cangjie-skill`
  - 代表“外部内容被蒸馏成可执行方法资产”，说明内容本身也可能变成 agent 接口的一部分。

## 当前判断

短期内，最先成熟的不是“所有创意环节都 agent 化”，而是以下几类半结构化场景：

- 设计到原型
- 页面到代码
- 代码到视频 demo
- 内容资料到 skill / SOP

这些方向的共同点是：原本就有一定结构、可验证中间态和明确交付格式。相比之下，纯审美驱动、完全开放式的创意环节，仍会更依赖人工判断。

## 对知识库的意义

- 这条线可以作为 `Agent-native 工具接口` 的下一阶段观察主线。
- 现阶段先不急着建独立主题地图，更适合继续挂在 `30-主题地图/Agent.md` 下观察。
- 如果后续样本继续增多，再考虑拆出 `AI 创意工具` 或 `设计/视频 Agent 工作流` 主题。

## 后续补证据方向

- 官方产品页和博客：Figma、Vercel、HeyGen、Remotion。
- 开源项目：是否有可操作的代码结构、render 流程和二次编辑能力。
- 真实工作流样本：产品 demo、研究摘要视频、设计交付、内容发布 SOP。
