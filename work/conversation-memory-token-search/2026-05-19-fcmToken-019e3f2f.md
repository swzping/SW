   位置：[account_settings/_controller.js](/Users/edy/Documents/fix/app-guardian/_src/override/_modules/account_settings/_controller.js:90)。

   注意：这里没有调用 `removeFcmToken()`，所以它只清本地，不一定通知后端解绑 FCM token。

**结论**
当前项目里真正执行 `removeFcmToken` mutation 的地方只有一个：

[account/_controller.js](/Users/edy/Documents/fix/app-guardian/_src/override/_modules/account/_controller.js:83)

```js
const onLogOut = async () => {

  await removeFcmToken({source: 'logout'});

它调用的是：

[fcmToken.js](/Users/edy/Documents/fix/app-guardian/_src/override/services/fcmToken.js:146)

```js
export const removeFcmToken = async ({source = 'logout'} = {}) => {
  ...
  mutation: REMOVE_FCM_TOKEN,
  variables: { deviceToken }
}
```

GraphQL mutation 定义在：

[mutations/fcmToken.js](/Users/edy/Documents/fix/app-guardian/_src/override/services/mutations/fcmToken.js:16)

所以如果服务端明确看到 `removeFcmToken` API 被调用，前端代码层面对应的意图是：**执行了这个 Account 页的 `onLogOut` 登出流程**。

**我排除掉的自动路径**

登录后注册 token 只会 insert，不会 remove：

- 登录成功调用 `insertAppToken`
- app 初始化调用 `updateFcmToken`
- token refresh 只做埋点 `trackObtainDeviceToken`
- 通知权限关闭只做 `trackPushUnsubscribe`
- session expired / unauthorized 只清本地登录态，不调用 `removeFcmToken`
- Settings 页登出、Account Categories 页登出也没有调用 `removeFcmToken`

特别是 session expired：

[useDataCustomer.js](/Users/edy/Documents/fix/app-guardian/_src/override/hooks/customer/useDataCustomer.js:75)

这里只有 `onSessionExpired()`，不会打 `removeFcmToken` API。

**一个关键细节**
当前 `_src/override/_modules/account/_view.js` 里虽然 controller 把 `onLogOut` 传进去了，但我没看到 view 实际绑定/调用它。它只在 props 里解构：

[account/_view.js](/Users/edy/Documents/fix/app-guardian/_src/override/_modules/account/_view.js:243)

也就是说，以当前代码看，这个 `removeFcmToken` 调用点存在，但在当前 Account 页面 UI 上不明显可达。若线上包和当前代码不完全一致，或者旧版本 Account 页曾经把 logout 按钮绑定到这个 `onLogOut`，那就能解释“登录后几分钟调用 removeFcmToken”。

**判断**
如果服务端日志时间点是用户刚登录几分钟后，并且不是用户主动点退出，那当前代码里没有发现自动触发 `removeFcmToken` 的逻辑。更可能是：

1. 线上包不是当前代码版本，旧 Account 页仍绑定了这个 logout。
2. 某处 UI/导航实际触发了 override account controller 的 `onLogOut`。
3. 服务端看到的是另一个端/旧版本 App 调用同名 mutation。
4. 用户点了某个“退出/切换账号”入口，但前端路径最后落到了 Account 的 `onLogOut`。

我之前做的 `Storage.clearExcept([FCM_TOKEN])` 只解决“本地被清空”的问题；**它不会阻止主动调用 `removeFcmToken` API**。如果现在要继续定位服务端这条调用，建议给 `removeFcmToken` mutation 请求额外带/打日志 `source`、页面名、app version、route name，这样能直接确认是不是 `source: logout` 这条前端路径。
