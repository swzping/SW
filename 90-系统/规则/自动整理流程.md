# 自动整理流程

这个规则用于让知识库主动推进，而不是要求用户每天手动建文件、判断分类。

## 核心原则

用户只负责提供想法、链接、截图、关键词或一句判断。整理助手负责判断放置位置、生成建议、等待确认，并在确认后更新知识库。

## 四类入口

| 入口 | 来源 | 作用 |
| --- | --- | --- |
| `00-入口/今日工作台.md` | 用户主动输入 | 想法、问题、当天要推进的事项。 |
| `10-输入流/日报/` | 每日自动抓取 | 当天 AI/LLM/Agent 新闻时间线。 |
| `10-输入流/概念雷达/每日筛选/` | 每日自动筛选 | 从日报中筛出的概念候选和处理建议。 |
| `10-输入流/概念雷达/长期追踪/` | 定期维护 | 长期跟踪的概念、模型、平台和工具观察清单。 |
| `10-输入流/原始资料/` | 人工或自动筛选 | 重要官方文档、论文、项目文档和可引用证据。 |
| `10-输入流/社媒收藏/` | 人工收藏或 Computer Use 采集 | 抖音、B 站、小红书等社媒内容的临时整理入口。 |

## 每日知识推进确认线

每天晚上读取用户主动想法和白天输入流沉淀。

整理助手必须：

1. 读取 `00-入口/今日工作台.md` 的 `待拆解想法` 和 `下一步问题`。
2. 读取 `00-入口/今日整理建议.md`。
3. 读取当天或最近的 `10-输入流/概念雷达/每日筛选/YYYY-MM-DD-概念筛选.md`。
4. 读取 `10-输入流/社媒收藏/` 下最近的抖音 AI 收藏批次和待处理 inbox。
5. 参考 `10-输入流/概念雷达/长期追踪/AI-Agent长期概念雷达.md` 和 `主流模型平台与工具产品雷达.md`。
6. 推荐 1 条来自工作台的主动想法、1 条来自输入流沉淀的外部变化/工具/概念，以及必要时 1 条来自社媒收藏的高价值候选。
7. 说明为什么建议推进，以及建议动作：保留问题、创建原子知识、更新主题地图、写研究备忘录或等待更多材料。
8. 先把候选写入 `00-入口/今日整理建议.md`，并在当前线程里直接向用户确认。
9. 用户可单选、可多选，也可全选。
10. 用户一旦勾选或明确回复要推进哪些候选，整理助手应在同一轮继续执行知识库推进，不停在候选层。

默认提问格式：

```text
今天我建议推进两类候选：

1. 主动想法：
「...」
建议动作：创建原子知识 / 更新主题地图 / 写研究备忘录 / 先保留为问题
原因：...

2. 输入流沉淀：
「...」
建议动作：创建原子知识 / 更新主题地图 / 写研究备忘录 / 先观察
原因：...

3. 社媒收藏候选：
「...」
建议动作：创建原子知识 / 更新主题地图 / 补找原始来源 / 先观察
原因：...

你勾选要推进的知识点，或回复“1 / 2 / 3 / 都推进 / 跳过 / 换一个”即可。勾选或确认后，整理助手继续推进到知识库。
```

## AI 情报扫描与输入流筛选线

每天早上执行外部情报扫描，并把输入流推进到“筛选和建议层”。

整理助手应该先抓取 AI/Agent/LLM 新闻，再扫描 `10-输入流/概念雷达/长期追踪/`。

### 重大 AI 新闻强制巡检

每天扫描时必须先做“官方发布哨兵”检查，不能只依赖搜索热度、GitHub Trending 或社区讨论。

强制检查对象：

- OpenAI：`openai.com/index`、`developers.openai.com/blog`、`developers.openai.com/api/docs/models`、OpenAI Help Center 里的 ChatGPT/Codex 模型可用性页面。
- Anthropic：`anthropic.com/news`、`anthropic.com/engineering`、Claude Code / Claude API / Agent Skills 官方文档。
- Google / Gemini：Google AI、Google Developers、Google Cloud AI 官方发布与模型文档。
- GitHub：GitHub Blog、GitHub Changelog、Copilot docs / changelog。
- Vercel：Vercel Blog、AI SDK、AI Gateway、v0 发布页。
- Figma：Figma Blog、Figma Make / Figma AI / Agent Skills 发布页。
- 其他重点平台：Cursor、Replit、Lovable、Bolt.new、OpenRouter、MCP 官方站点。

以下内容一旦在官方源出现，必须进入当日日报的 `热点新闻 Top 10` 或 `模型 / 论文 / API` 小节：

- 新旗舰模型、模型家族或重要模型版本发布，例如 `GPT-5.6`、Claude / Gemini 重大版本。
- API models 文档新增模型 ID、别名、上下文窗口、价格、工具能力、reasoning level 或可用区域。
- ChatGPT、Codex、Claude Code、Copilot、Cursor 等核心产品的模型可用性变化。
- 新的工具调用、computer use、multi-agent、memory、evals、observability、安全授权能力。
- 重大价格变化、限额变化、默认模型切换、模型退场或迁移时间表。

重大 AI 新闻的判断标准：

- 官方源明确发布，优先级高于社交热度。
- 影响 Codex、Claude Code、Cursor、Copilot、v0、Figma Make、Lovable、Bolt.new、Replit Agent 等主流工作流。
- 影响模型能力、成本、上下文窗口、工具调用、computer use、前端/设计生成、知识工作、agent 执行结构或企业治理。

如果发现当天日报已生成但漏掉重大官方发布：

1. 立即回填当日日报、每日概念筛选、今日整理建议。
2. 必要时更新 `主流模型平台与工具产品雷达.md` 或 `AI-Agent长期概念雷达.md`。
3. 在日报中明确标注“初版漏掉，已回填”，并说明漏报原因。
4. 更新自动化 memory，避免下次重复漏报同类来源。

整理助手应该生成：

- `10-输入流/日报/AI圈新闻-YYYY-MM-DD.md`
- `10-输入流/概念雷达/每日筛选/YYYY-MM-DD-概念筛选.md`
- `00-入口/今日整理建议.md`

日报默认应包含一个 `GitHub 热门项目观察` 小节，至少覆盖：

- `Star 增长最快`：近 24 小时或近期增长最快的 AI/Agent/MCP/skill 相关项目。
- `高 Star skill / 技能项目`：累计 star 较高、且与 skill、agent workflow、memory、browser、evals、context engineering 相关的项目。

对入选项目，默认尽量补以下信息：

- GitHub 仓库链接。
- `项目归类`。
- 它解决什么问题。
- 适合哪些行业。
- 适合哪些工作场景。

`项目归类` 默认明确标记项目属于什么，不只写项目名。可用分类包括：

- `skill`
- `coding agent`
- `browser / MCP 工具`
- `memory 工具`
- `evals / observability 工具`
- `设计工具`
- `视频工具`
- `AI app builder`
- `基础设施 / gateway`
- `其他`

示例：

- `HyperFrames` 应标记为 `视频工具`，不是 `skill`。

默认行业分类：

- 前端研发
- 通用软件工程
- 设计协作
- 内容生产
- 数据分析
- 客服销售
- 运营投放
- 教育研究
- 企业内控 / 知识管理
- 垂直行业工作台

默认工作场景分类：

- 代码生成
- 代码审查
- 前端调试
- 浏览器自动化
- 知识检索 / RAG
- 长期记忆
- 工作流编排
- 评测 / 观测
- 安全授权
- 设计到代码
- 文档整理
- 异步任务执行

`今日整理建议.md` 包含：

- 今日最值得关注的 3-5 个概念。
- 建议创建的原子知识。
- 建议更新的主题地图。
- 建议放入原始资料的重要证据。
- 需要用户确认的问题。

如果某个概念连续出现或重要性变化，再更新：

```text
10-输入流/概念雷达/长期追踪/AI-Agent长期概念雷达.md
```

输入流处理默认不直接大量创建原子知识，避免自动内容污染知识库。

GitHub 热门项目本身不自动进入长期追踪；只有当它代表稳定能力方向、连续出现，或显著改变你对某类工作流的判断时，才升级为长期跟踪对象。

## 确认后执行规则

当用户确认某条建议后：

1. 创建或更新 `20-原子知识/`。
2. 更新相关 `30-主题地图/` 的链接和当前判断。
3. 更新 `00-入口/今日工作台.md`。
4. 如果用到重要来源，再把来源登记到 `10-输入流/原始资料/`。

如果用户一次确认多条建议：

1. 允许单选、双选或全选。
2. 按候选顺序依次推进，避免漏掉其中一条。
3. 回写结果时明确说明本轮实际推进了哪些条目。

## 社媒收藏整理线

当用户说“整理抖音收藏”“整理这批社媒收藏”或提供抖音链接、截图、标题时，整理助手应该：

1. 先把材料登记到 `10-输入流/社媒收藏/待处理/抖音AI收藏-inbox.md` 或对应批次文件。
2. 按 `90-系统/模板/社媒AI收藏模板.md` 生成结构化条目。
3. 对每条内容判断：保留输入流、创建原子知识、更新主题地图、写研究备忘录或丢弃。
4. 只把能形成判断、方法、案例或长期问题的内容升级到正式知识区。
5. 如果需要采集收藏页，由用户先完成登录；整理助手可用 Computer Use 读取页面，但不保存登录凭据，不绕过验证码。

社媒内容默认不是可引用证据。若内容提到官方文档、论文、开源项目或产品发布，应优先寻找原始来源，再决定是否放入 `10-输入流/原始资料/`。

## 原始资料使用规则

原始资料不是收藏夹。只有以下内容进入：

- 官方文档。
- 重要论文。
- 关键项目文档。
- 未来写判断时需要引用的证据。

普通文章、随手链接和未消化想法，先放工作台。

## 自动化节奏

- 10:00：AI 情报扫描与输入流筛选，生成日报、每日概念筛选和 `00-入口/今日整理建议.md`。
- 18:00：读取工作台、今日整理建议、每日概念筛选和社媒收藏，推荐主动想法、输入流候选和社媒收藏候选；先等待用户勾选或确认，再在同一轮继续推进到知识库。

## 不做什么

- 不自动把所有新闻变成原子知识。
- 不把普通链接都放进原始资料。
- 不在没有用户确认的情况下推进用户主动想法。
- 不在没有用户确认的情况下推进输入流候选为正式知识。
- 不追求当天清空所有输入。
