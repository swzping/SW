# 自生长规则

## 一句话理论

LLM Knowledge Base 的自生长，不靠无限收藏资料，而靠“输入筛选、原子化、链接、综合、再提问”的闭环。

## 五层结构

1. 输入层：接收日报、网页、论文、项目、对话记录。
2. 原子层：把输入拆成最小可复用知识单元。
3. 主题层：当同类原子知识反复出现时，升级成主题地图。
4. 综合层：定期把主题地图里的证据改写成趋势判断、研究备忘录或行动建议。
5. 反馈层：每次综合都留下下一步问题，驱动新的输入。

## 信息进入规则

一条信息进入知识库前，必须回答三个问题：

- 它说明了什么事实？
- 它改变了什么判断？
- 它应该链接到哪个主题？

回答不了，就暂时留在 `10-输入流/`，不要急着放进原子知识。

## 原子笔记规则

- 一篇原子笔记只表达一个概念、判断或证据。
- 标题要可复用，例如 `Context Engineering`，不要写成 `今天看到的一篇文章`。
- 必须包含来源、我的判断、相关主题和下一步问题。
- 如果一条笔记可以拆成两个判断，就拆成两篇。

## 主题地图升级规则

当某个标签或概念出现 3 条以上原子笔记时，创建或更新一个主题地图。

主题地图不追求完整百科，而要回答：

- 这个主题是什么？
- 为什么现在重要？
- 关键分支有哪些？
- 已有哪些证据？
- 我目前的判断是什么？
- 下一步应该追踪什么？

## 综合输出规则

每周至少做一次综合，优先写：

- 本周最重要的 3 个变化
- 哪些只是噪音
- 哪些可能成为长期趋势
- 对开发者、产品、公司或个人学习的影响
- 下周继续观察的问题

## 清理规则

- 30 天未处理的输入，如果没有明显价值，删除或归档。
- 重复表达的原子笔记要合并。
- 主题地图超过 2000 字时，拆出子主题。
