## 收藏反映出的真实主线

这些收藏表面上很杂，实际反复指向同一个目标：建立一套能替个人持续执行工作的 AI 系统。

这套系统可以拆成四层：

1. `执行层`：Codex、Claude Code、桌面/浏览器控制，负责真正动手完成任务。
2. `方法层`：Skills、自定义指令、工作流，把一次成功做法变成可复用能力。
3. `记忆与连接层`：Obsidian、MCP、外部数据库、飞书多维表，让 Agent 能读取资料、保存状态、连接业务。
4. `可靠性层`：工程约束、评测、权限、日志、成本、数据安全，保证结果不是一次性演示。

因此，不建议继续把学习重点放在“记住更多 AI 工具”。更值得形成的核心能力是：`把任务拆清楚 -> 让 Agent 调用工具执行 -> 检查结果 -> 把有效方法固化成 Skill`。

## 应该优先学习什么

### 第一优先级：Coding Agent 的稳定使用

目标不是学会聊天，而是能把一个真实任务完整委派出去。

重点学习：

- 如何写清楚目标、输入、约束、验收标准。
- 如何拆分长任务并管理上下文，避免“失忆”和任务漂移。
- 如何让 Agent 读写文件、运行命令、控制浏览器或桌面软件。
- 如何让 Agent 在交付前测试、截图、复核和留下证据。
- Codex 与 Claude Code 的分工边界，不必追求谁替代谁。

对应收藏：`Codex 自动下载数据脚本`、`Codex 自定义指令这样写`、`没有 Codex，一个 Claude Code不是换模型，是隔离上下文`、`Codex 电脑操控功能正式上...`、`工业级 AI Agent，Node.js...`。

### 第二优先级：Skill 与工作流资产化

这是收藏中最值得长期投入的方向。Skill 不应只是“装得多”，而应把自己的高频任务固化下来。

重点学习：

- 一个 Skill 的最小结构：任务说明、输入输出、步骤、工具、边界、失败处理。
- 如何从一次成功执行记录中提炼 Skill。
- 如何给 Skill 做版本管理、测试样例和失败案例。
- 如何区分知识笔记与可执行 Skill：前者回答“是什么/为什么”，后者回答“怎么稳定完成”。

第一批最适合自己制作的 Skill：

1. `抖音收藏采集与去重`
2. `视频/文章证据核验与摘要`
3. `资料升级为原子知识和主题地图`
4. `A 股数据收集、复盘与验证`
5. `FFmpeg 视频处理`或`Manim 可视化`

对应收藏：`开源仓颉 Skill：蒸馏任何视频`、`这 5 个 Skill，让 AI 替你打工`、`下载了很多 Skill 怕忘记`、`CodeX 只需要这 5 个 Skills`、`FFmpeg Skill`、`Manim Skill`。

### 第三优先级：个人知识库、MCP 与 Agent Memory

你已经在做这件事，价值高于再收藏一批工具清单。目标是让知识库从“存文件”变成 Agent 可读、可写、可追踪来源的工作台。

重点学习：

- 输入流、原始证据、原子知识、主题地图、Skill 的分层。
- MCP 如何暴露本地知识、工具和数据，同时控制权限。
- 长期记忆应保存哪些内容：事实、决策、偏好、失败、下一步，而不是保存所有聊天。
- 每个结论如何回到原标题、链接、截图或官方资料。

对应收藏：`Codex + Obsidian 搭自生长知识库`、`如何让 AI 自动管理你的私有资料`、`开源 IMA 个人知识库工作台 / ima-skills`、`Agent memory / 外部数据库`、`Claude Code 总失忆？`。

### 第四优先级：Agent 工程化，而不是盲目多 Agent

先做好一个 Agent 的闭环，再学习多 Agent。多 Agent 的价值来自明确分工、交接和审查，不来自角色数量。

重点学习：

- 工具调用、状态管理、重试和超时。
- trace、日志、成本和结果评测。
- human-in-the-loop、权限边界和数据安全。
- 多 Agent 的 planner、executor、reviewer 分工，以及何时不需要多 Agent。

对应收藏：`Agent 的 7 种架构`、`多 Agent 编排设计`、`Team Agent：飞书多维表 + 智能体`、`大模型权重与数据安全管控`、`前端工程化四层锁`。

## 两条应用支线

### 支线 A：AI 投研与 A 股数据

这条线与你现有的数据技能最接近，容易做出真实项目。学习顺序应是：`可靠数据源 -> 可复现分析 -> 回测验证 -> 风险控制 -> 纸面交易`，不要从“AI 股神”或自动下单开始。

建议先做一个投研助理：每天采集真实行情、公告和新闻，输出有来源的摘要；所有策略结论必须有样本、回测和次日验证。

重点关注：`a-stock-data / 让 AI 查 A 股真数据`、`TradingAgents 框架`、`Claude Code 搭建大 A 稳定的数据源`、`AI 对话 + 多智能体大 A 数据分析`。

### 支线 B：AI 内容生产与设计工程化

值得学习的是“完整生产链”，不是单个出片神器。链路包括：选题、资料、脚本、画面、语音、剪辑、发布、数据复盘。

优先关注可控制、可组合的工程工具，如 FFmpeg、Manim、设计系统和自动发布；对“一键爆款”“全自动赚钱”保持低优先级。

重点关注：`FFmpeg Skill`、`Manim Skill`、`Codex 自媒体平台自动发布`、`前端面试官：你让 AI 生成组件，怎么保证不重复造轮子？`、`别再用提示词调教 AI 了！2026 前端工程化四层锁`。

## 未来 30 天的学习顺序

### 第 1 周：把 Agent 用稳

- 选一个真实任务，例如“继续整理抖音收藏并输出证据表”。
- 明确输入、去重规则、输出字段和验收条件。
- 记录失败点：页面滚动、OCR 错字、链接缺失、重复条目。

交付物：一份可重复执行的 SOP，而不是更多工具收藏。

### 第 2 周：把 SOP 做成 Skill

- 将采集、OCR、分类、去重、补链接、总结拆成明确步骤。
- 为每一步定义输入输出和失败处理。
- 用 10 条新收藏回放测试，检查能否稳定复现。

交付物：`抖音 AI 收藏整理 Skill v1`。

### 第 3 周：接入知识库与记忆

- 让 Agent 能检索旧证据表，自动避免重复。
- 新结论必须引用原标题、链接或截图。
- 只把高价值且已核验的内容升级到原子知识。

交付物：从收藏到证据、原子知识、主题地图的完整闭环。

### 第 4 周：做一个垂直应用

- 优先建议做 `AI 投研助理`，因为已有 A 股数据能力；也可选择内容生产流水线。
- 只做一个窄任务，持续运行 5-7 天。
- 记录准确率、人工修改量、耗时、成本和失败原因。

交付物：一个有真实数据和复盘记录的 Agent，而不是演示视频。

## 应该长期关注的指标

不要只关注新模型和新插件，重点看这些变化：

- Agent 能否连续完成跨文件、跨应用、跨天任务。
- Skill 是否可版本化、可测试、可迁移到不同 Agent。
- MCP/连接器是否有清晰权限、确认和审计机制。
- Agent memory 是否可控、可删、可追溯来源。
- AI 生成代码是否进入测试、组件复用、代码审查和发布流程。
- AI Gateway 是否提供稳定路由、fallback、成本和日志，而不只是低价 Token。
- 多 Agent 是否真实提升交付质量，还是只增加沟通成本。
- 投研系统是否使用真实数据、避免未来函数、提供样本外验证。

## 暂时少花时间的内容

- “AI 红利”“普通人翻身”“月入多少”但没有流程和数据的内容。
- 只按数量罗列的“5 个神器”“10 个必装插件”。
- 只有 Star 数、没有适用边界和维护状态的开源项目。
- 没有数据源、回测、风控的“AI 炒股”结论。
- 一键出片、网站克隆等只有效果展示，没有成本、版权和人工修改量的数据。
- 把多 Agent 角色数量当作系统能力的内容。

## 一句话结论

你的最佳学习方向不是泛泛地“学 AI”，而是成为能把个人方法、知识和业务流程封装成可靠 Agent 工作流的人。主修 `Coding Agent + Skill + 知识库/MCP + 工程化验证`，再用 `AI 投研`或`内容生产`做垂直实战。
