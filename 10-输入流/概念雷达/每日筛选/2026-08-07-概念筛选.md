## 今天筛出的 5 个值得关注概念

1. `统一 AI 工作台`
   - 为什么值得关注：OpenAI 已连续用 `ChatGPT + Codex + browser-based work` 来讲统一入口，说明工作台化正在压过“单点 agent 产品”叙事。
   - 属于：`长期能力方向`
   - 对你有什么影响：直接影响你后续如何看 `Codex`、`browser tooling`、`connectors`、`handoff`、`长任务执行`。

2. `Skill 进入官方 agent runtime`
   - 为什么值得关注：OpenAI Developers、Figma、Replit 近期都在强化 `skill`，说明它已经不只是 prompt 包，而是 agent 组织层。
   - 属于：`长期能力方向`
   - 对你有什么影响：会直接影响你自己的 `knowledge-workspace-mcp`、`team workflow`、`方法资产沉淀`。

3. `AI app builder API 化`
   - 为什么值得关注：`v0 API` 让 builder 从聊天式产品变成可被程序和外部工作流调用的能力层。
   - 属于：`长期能力方向`
   - 对你有什么影响：直接关联 `设计到代码`、`异步任务执行`、`工作流编排`、`前端原型生产线`。

4. `design agent local code / skill 协作层`
   - 为什么值得关注：Figma Make 的 `local code` 与 `got skills` 这组信号，说明设计 agent 正从“生成”升级到“基于上下文协作”。
   - 属于：`长期能力方向`
   - 对你有什么影响：会影响你对 `Figma Make`、`v0`、`Lovable`、`前端协作工作台` 的整体判断。

5. `team-level memory hub`
   - 为什么值得关注：GitHub 热门项目今天继续把 `memory + skill + wiki + code graph` 作为统一资产层推进。
   - 属于：`长期能力方向`
   - 对你有什么影响：会影响你判断未来 memory 是“外挂”还是“组织中台”。

## 今日判断

今天最关键的变化不是“又有几个新工具”，而是主流平台都在把 agent 能力往三层结构推进：

1. `工作台层`
   - ChatGPT + Codex
   - browser-based work
   - long-running tasks

2. `组织层`
   - skills
   - team memory
   - review harness

3. `能力层`
   - v0 API
   - local code
   - browser / MCP tools

这说明 AI/Agent 的主线继续从“单次生成”转向“可组织、可调用、可协作、可接入真实工作流”。
