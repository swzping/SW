3. `agent automation controls` 是否开始成为任务系统里的默认边界能力

5. `skill / harness / memory / gateway` 是否正在形成一组可复用工程层，而不是分散热词

## 今天值得关注的概念

### 1. `MCP 进入 spec / host 工程期`

- 为什么值得关注：`Release Candidate 2026-07-28`、`GitHub MCP Server supports the next MCP specification`、`MCP Apps`、`Enterprise-Managed Authorization` 这组信号已经形成连续证据。
- 今天的判断：MCP 的重点已进一步从“server 多不多”转向 `spec 兼容、host 能力、授权治理、app 形态、浏览器接入`。
- 建议动作：更新长期追踪文件中的 MCP 判断。

### 2. `Review policy as code`

- 为什么值得关注：OpenAI `Custom Code Review rules for Codex` 与 GitHub `Copilot code review`、`Issues automation controls` 已在同一周内组成较完整证据链。
- 今天的判断：coding agent 的门槛已经从“会不会写代码”升级为“能不能在团队规范、任务边界和默认检查中稳定运行”。
- 建议动作：继续保留为高优先级原子知识候选。

### 3. `Agent automation boundary`

- 为什么值得关注：GitHub 已开始显式提供 issue 层的 automation controls。
- 今天的判断：以后比较 Agent 平台，不应该只看自动化能力强弱，还要看 `谁定义权限边界、回退路径和人工接管点`。
- 建议动作：建议挂在 `Agent / governance` 主线，而不是单独追一个产品更新。

### 4. `Browser-native tooling`

- 为什么值得关注：Safari MCP server、Playwright MCP、browser-use、Chrome DevTools MCP 一起说明，前端 Agent 的真实可用性越来越取决于浏览器可见性。
- 今天的判断：这不是短期工具热度，而是前端调试、截图验证、console 检查和页面接管的基础层。
- 建议动作：建议继续保留为前端相关主题地图补充项。

### 5. `Skill / harness / memory / gateway 组合层`

- 为什么值得关注：今天 GitHub 高热项目并不指向同一个产品方向，但都在给 `skills`、`harness engineering`、`memory`、`auth gateway` 补样本。
- 今天的判断：长期价值不在单个仓库，而在它们共同证明 Agent 工程层正在被拆成几块稳定能力：`做事方法`、`执行外壳`、`长期记忆`、`授权路由`。
- 建议动作：建议继续保留在长期概念雷达，不急着新增过多原子知识。
