2. `MCP` 是否已经从协议进入工程稳定期
3. `browser-native agent tooling` 是否开始成为前端调试默认能力

5. `design agent workspace` 是否继续强于单点 AI app builder 叙事

## 今天值得关注的概念

### 1. `Review policy as code`

- 为什么值得关注：Codex 与 Copilot 两侧都出现了更明确的 review 规则、配置文件、setup steps、网络控制与接管结构。
- 今天的判断：这已经不是零散功能，而是在说明 coding agent 的门槛正从“能写代码”转向“能被团队工程规范收编”。
- 建议动作：建议升级为高优先级原子知识候选。

### 2. `MCP 进入工程稳定期`

- 为什么值得关注：`Release Candidate 2026-07-28`、`MCP Apps`、`Enterprise-Managed Authorization`、`Safari MCP server` 已形成连续官方证据链。
- 今天的判断：MCP 的重点已经从“server 多不多”转向 `授权治理、app 形态、浏览器接入、SDK 迁移成本`。
- 建议动作：保留长期追踪，并更新长期判断。

### 3. `Browser-native agent tooling`

- 为什么值得关注：Safari MCP server 与 Chrome DevTools MCP 一起说明，浏览器调试能力正在以更标准的接口进入 agent。
- 今天的判断：这对前端开发比很多模型新闻更重要，因为它决定 agent 能否真正看见页面、理解运行态、执行调试闭环。
- 建议动作：建议作为主题地图补充项，不急着单独新建长期条目。

### 4. `AI gateway / auth gateway / artifact handoff`

- 为什么值得关注：OmniRoute、open-connector、waggle 这类热门仓库不是同一个产品方向，但在共同证明 `路由 + 授权 + 交接介质` 正在组合成下一层基础设施。
- 今天的判断：长期价值不在“支持多少模型”，而在 `可治理、可降级、可交接、可压缩上下文`。
- 建议动作：建议继续保留在 `AI 基础设施` 主线，而不是追单个仓库。

### 5. `Design agent workspace`

- 为什么值得关注：Figma Make 持续把 `GPT-5.6、skills、code layers / Buzz、本地代码协作` 组合在一起。
- 今天的判断：设计工具的长期主线不是“更快生成”，而是 `设计上下文、代码上下文和协作动作` 被统一到 agent workspace。
- 建议动作：建议作为设计类主题地图更新候选。
