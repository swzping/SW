# 2026-07-28 概念筛选

日期：2026-07-28

## 今日先看什么

今天优先看五条会继续影响工程实践的方向：

1. `MCP` 是否已经从“工具连接协议”进一步升级成 `spec / host / SDK / auth` 的工程标准层
2. `review policy + automation boundary` 是否正在收敛成 coding agent 默认工程层
3. `browser-native tooling` 是否正在稳定进入前端调试主工作流
4. `skill / memory / harness / gateway` 是否已经形成可拆分的稳定能力层
5. `模型上限` 与 `平台工作流层` 的关系是否继续向 `workflow layer > raw model` 收敛

## 今天值得关注的概念

### 1. `MCP 进入 spec / host 工程期`

- 为什么值得关注：`2026-07-28 MCP RC` 已经把 `stateless core`、`Tasks extension`、`MCP Apps`、`authorization hardening`、`formal deprecation policy` 写成同一版升级路线。
- 今天的判断：MCP 的重点已经进一步从“能不能接工具”转向 `协议兼容、host 能力、SDK 迁移、企业授权、browser-native workflow`。
- 建议动作：更新长期追踪文件中的 MCP 判断。

### 2. `Review policy + automation boundary`

- 为什么值得关注：`Codex review rules`、`GitHub Issues automation controls`、`GitHub MCP next spec` 这一组信号，说明 coding agent 不只是自动写代码，而是在被产品化为可治理系统。
- 今天的判断：coding agent 的门槛正在从“会不会生成代码”升级为“能不能在规则、边界、接管和审计里稳定运行”。
- 建议动作：继续保留为高优先级原子知识候选。

### 3. `Browser-native tooling`

- 为什么值得关注：`Safari MCP server`、`Playwright MCP`、`browser-use` 已经连续多天给出同方向证据。
- 今天的判断：这不是单个工具热度，而是前端 agent 是否真的能闭环做页面调试、截图验证、console 检查和浏览器接管的基础层。
- 建议动作：继续保留为长期能力方向。

### 4. `Skill / memory / harness / gateway 组合层`

- 为什么值得关注：今天的 GitHub 热门样本并不指向同一个产品，但都在为 `做事方法`、`执行外壳`、`长期记忆`、`授权路由` 这四层补样本。
- 今天的判断：长期价值不在某个仓库，而在这四层能力正在逐步稳定下来。
- 建议动作：保留在长期概念雷达，不急着新增过多原子知识。

### 5. `Workflow layer > raw model`

- 为什么值得关注：`Claude Opus 5` 同时被 Anthropic 与 GitHub Copilot 吸收，继续说明模型能力会重要，但最终进入日常工作的还是平台工作流层。
- 今天的判断：如果没有 `review rules / approvals / automation controls / observability / browser tooling`，模型上限本身并不会自然变成稳定生产力。
- 建议动作：继续作为长期判断保留。
