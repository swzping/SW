## 先给结论

今天最该筛出来的，不是“又多了几个能写代码的 agent”，而是下面四条已经被官方博客、平台基建和 GitHub 项目同时强化的长期能力方向：

1. `私有 MCP 接入` 正在进入真实生产前提层。
2. `前端友好的 agent 基建` 正在从工具碎片走向完整 stack。
3. `browser / MCP / 调试` 正在从概念讨论继续落到原生工具层。
4. `面向 agent 的文档与 skill 资产` 正在从零散经验变成项目形态。

## 今天值得关注的概念

### 1. 私有 MCP 接入已经从“想法”进入“落地条件”

- 来自信号：
  - OpenAI `Making private MCP servers reachable without making them public`
  - Codex Remote 对 host / workspace / worktree 边界的强调
- 为什么值得关注：
  - 这意味着今后的高价值工具接入，很可能不是公开互联网工具，而是团队内部 API、知识库、设计系统、浏览器调试能力和私有数据面。
- 建议动作：
  - 作为 `MCP` 的新判断写进长期观察，但不单独追成一个新热词。
- 判断：
  - 长期能力方向，重要性 `A`。

### 2. 前端友好的 agent 基建正在成型

- 来自信号：
  - Vercel `AI SDK 7`
  - `The Agent Stack`
  - `Vercel Connect`
  - `AI Gateway` 的生产指数和 voice 支持
- 为什么值得关注：
  - 这些不是孤立产品更新，而是在把 `TS SDK + workflow + auth + routing + UI` 收成一条链。
- 建议动作：
  - 更新长期产品雷达里 `Vercel AI SDK / AI Gateway` 的判断，必要时提升优先级。
- 判断：
  - 长期能力方向，重要性 `A`。

### 3. Browser-native MCP 继续强化前端调试主线

- 来自信号：
  - WebKit `Safari MCP server`
  - `playwright-mcp`
  - `browser-use`
- 为什么值得关注：
  - 说明浏览器不只是被“自动化”，而是正在被纳入标准化 agent 接口层。
- 建议动作：
  - 挂在 `MCP` 与 `Frontend QA / Browser Use` 的交叉观察下。
- 判断：
  - 长期能力方向，重要性 `A-`。

### 4. Agent 文档资产化正在升温

- 来自信号：
  - `openwiki`
  - `davidondrej/skills`
  - `codex-orange-book`
  - `claude-cookbooks`

  - 它们共同说明：项目文档、操作经验、团队规则，正在从“给人看”转向“也给 agent 消化”。
- 建议动作：
  - 值得拆成一条轻量原子知识候选，但不需要把每个仓库都纳入长期雷达。
- 判断：
  - 长期能力方向，重要性 `B+`。

### 5. Memory / Evals 今天更像底噪主线，不是新增爆点

- 来自信号：
  - `mem0`
  - `langfuse`
  - Anthropic 的 managed agents / containment 讨论
- 为什么值得关注：
  - 它依然重要，但今天没有出现比 `私有 MCP`、`Agent Stack` 更强的新升级信号。
- 建议动作：
  - 继续放在长期主线，不急着新增很多知识卡片。
- 判断：
  - 长期能力方向，重要性 `A-`，但今天不是第一优先。
