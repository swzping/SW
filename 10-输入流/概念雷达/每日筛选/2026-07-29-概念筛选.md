## 今天值得关注的概念

### 1. `MCP 进入 spec / host 工程期`

- 为什么值得关注：`2026-07-28 MCP RC` 已经把 `stateless core`、`Tasks extension`、`MCP Apps`、`authorization hardening`、`formal deprecation policy` 写成同一版升级路线。
- 今天的判断：MCP 的重点已经进一步从“能不能接工具”转向 `协议兼容、host 能力、SDK 迁移、企业授权、browser-native workflow`。
- 建议动作：更新长期追踪文件中的 MCP / 工程化判断。

### 2. `Review policy + automation boundary`

- 为什么值得关注：`Codex review rules`、`GitHub Issues automation controls`、`Claude Opus 5 in Copilot` 继续说明，coding agent 正在被产品化为可治理系统。
- 今天的判断：coding agent 的门槛正在从“会不会生成代码”升级为“能不能在规则、边界、接管和审计里稳定运行”。
- 建议动作：继续保留为高优先级原子知识候选。

### 3. `Browser-native tooling`

- 为什么值得关注：`Safari MCP server`、`playwright-mcp`、`browser-use` 已经连续多天给出同方向证据。
- 今天的判断：这不是单个工具热度，而是前端 agent 是否真的能闭环做页面调试、截图验证、console 检查和浏览器接管的基础层。
- 建议动作：继续保留为长期能力方向，不因单日涨星新增太多仓库笔记。

### 4. `Skill management layer`

- 为什么值得关注：今天的 `book-to-skill`、`OpenSpace`、`ECC` 一起说明，skill 正在从“技能包”长到 `资料蒸馏、管理层、执行 harness` 三种更明确的产品形态。
- 今天的判断：这条线已经不只是平台内功能，而是在形成可独立比较的工程层。
- 建议动作：更新长期追踪文件中的 `Agent Skill` 判断，但不急着为每个仓库单独建长期条目。

### 5. `Memory / context / skill 合流`

- 为什么值得关注：`OpenViking` 直接把 `memory + RAG + skills` 收进同一个 `context database` 叙事，说明 agent 上下文底座正在开始合流。
- 今天的判断：长期价值不在某个新仓库，而在 `长期记忆、检索、技能注入` 三层正在从松散组合走向统一底座。
- 建议动作：先保留在长期概念雷达，不自动推进大量原子知识。
