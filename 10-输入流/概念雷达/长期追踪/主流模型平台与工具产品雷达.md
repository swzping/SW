# 主流模型平台与工具产品雷达

最近更新：2026-09-03

用途：这份雷达专门跟踪会直接影响我实际开发工作流的模型、平台、Agent、AI app builder、前端/设计工具。它不追求覆盖所有产品，而是优先收录市面上流行、被开发者持续讨论、或有官方生态支撑的工具。

## 判断标准

一个工具进入这份雷达，至少满足其中一条：

- 对前端开发、代码生成、调试、测试、交付有直接影响。
- 有官方文档、产品页面、SDK、开源仓库或明确生态。
- 在开发者社区或行业评测中反复出现。
- 能启发我设计自己的 MCP、Agent workflow 或前端工作台。

## 优先级

| 优先级 | 含义 | 动作 |
| --- | --- | --- |
| A | 应持续关注和试用 | 建主题或研究备忘录，定期复盘。 |
| B | 值得了解和对比 | 建产品项目笔记，按需试用。 |
| C | 观察即可 | 放在雷达里，不急着深入。 |

## 一、编码 Agent 与开发环境

| Cursor | A | Agentic IDE | 开发者中高频使用的 AI IDE，强调把任务交给 agent，同时保留人的决策。 | 值得持续观察 `本地 IDE + 云端 background agent + model routing / swarm economics + PR babysitting` 这一形态。`Cursor Router` 已把跨 desktop / web / iOS / CLI / SDK 的模型路由明确产品化，说明它的重点不再只是 IDE 内补全，而是 `routing layer + agent runtime + review loop`。`2026-08-27` 的 changelog 进一步补出一条很强的新证据：`Agents in every repo` 与 `App extensions for Cursor repos` 说明它正在把 `repo + PR + app integration + agent` 收进同一个仓库级工作面，这让它更像 `repo-level agent workspace`，而不只是一个带 agent 的编辑器。`2026-09-03` 的 `self-hosted machines` 则把这条线继续推进到 `execution location governance`：后续更值得观察的已经不只是 repo 内怎么调 agent，而是企业是否能把执行环境、网络边界、密钥和依赖控制一起收进默认工作面。 |
| GitHub Copilot / Copilot Cloud Agent | A | IDE + 云端 coding agent | 直接嵌入 GitHub 与 VS Code，云端 agent 可以研究仓库、创建分支、改代码、提交 PR。 | 对企业和 GitHub 工作流影响很大，且已进入 `browser tools + vision + MCP in code review + session streaming + agent skills` 阶段；当前 Cloud Agent 文档已把 `default MCP servers`、`issue / PR delegation`、`task metrics` 写成默认结构。`Copilot app` 已在 `2026-07-07` 向所有 Copilot 方案开放，`Copilot usage metrics API` 与 `impact dashboard` 也在 `2026-07-17` 到 `2026-07-22` 连续补齐；`Claude Opus 5 in GitHub Copilot`、`Issues automation controls`、`GitHub MCP Server next spec`、`Copilot code review: Agent skills and MCP now generally available` 与 `GitHub Models retired` 则继续补强 `多模型编排 + 自动化边界 + 审查时上下文注入 + 协议兼容 + workflow layer` 这组平台能力，进一步说明竞争点正转向 `workflow layer > model catalog > observability > governance`。`2026-08-03` 新增的 `reasoning level` 与 `comment-triggered automations` 又补了两条控制面证据，说明 GitHub 正在把 `推理深度 + 触发入口 + 异步执行` 收进默认产品层。`2026-08-12` 的 `Agent Plugins 1.0` 则进一步把 `skills + MCP servers` 做成跨客户端插件标准，说明 GitHub 已开始把 `plugin packaging + MCP allowlists + enterprise settings` 收进默认治理层；`2026-08-13` 的 `Gemini 3.7 Flash in Copilot` 与 `2026-08-14` 的 `Grok 4.6 in Copilot` 又连续补了两条模型侧证据，说明它的重点已经不只是“多一个模型”，而是 `模型选择速度 + 插件层 + workflow policy` 一起进入产品层。`2026-08-18` 的 `Enterprise managed settings in GitHub Copilot for JetBrains` 再补出一条很强的新证据：`enterprise settings + plugin governance` 已不只存在于 VS Code/Copilot App，而是在继续扩成跨 IDE 的组织控制层。`2026-08-21` 的 `The new GitHub Copilot experience in Slack` 与 `Shared agentic work with GitHub Copilot in Microsoft Teams` 则进一步说明，GitHub 现在也在把 `team chat entry` 收进默认工作面，后续更值得观察的是 `chat approval / async handoff / shared task visibility` 是否进入标准工作流。`2026-08-31` 到 `2026-09-02` 这一组更新又把 `跨应用 session visibility`、`budget expiration`、`code review approve PR`、`content exclusions`、`任意默认模型的企业托管设置` 与 `Claude Fable 5.1` 接入写进正式产品层，说明 GitHub 正在继续把 `agent governance + repo-level workspace + model default governance + frontier-model absorption` 一起收进默认控制面。 |

## 二、AI App Builder / Vibe Coding

| 名称 | 优先级 | 类型 | 我为什么要关注 | 当前判断 |
| --- | --- | --- | --- | --- |
| v0 | A | Vercel AI app builder | 从 prompt 生成可运行 Web app，可发布、同步 GitHub；天然贴近 React/Next/Vercel 生态。 | 前端开发者必须关注，尤其是 UI 原型和组件生成；`2026-08-05` 的 `v0 API` 说明它已经从单一交互工具走向可编排、可集成的程序化能力层，后续更值得看它如何与 `AI Gateway`、部署治理层、团队 workflow、权限边界和异步任务执行协同。 |
| Lovable | A | Full-stack AI development platform | 用自然语言构建、迭代、部署 Web app，强调真实代码、安全和企业治理。 | 适合快速产品原型，对前端/全栈交付有实际影响。`Your Lovable app now works inside ChatGPT and Claude` 与 `App user connectors` 进一步说明，它正在把 `AI app builder + MCP / agent entry + per-user connectors + enterprise governance` 收进同一层；今天更明确的判断是，后续更值得看 `connectors / approvals / audit / auth / user-scoped permissions` 是否继续成为默认能力。 |
| Bolt.new | A | Browser-based full-stack AI agent | 浏览器里 prompt、运行、编辑、部署全栈应用，开源生态也值得看。 | 适合观察 WebContainer/浏览器 IDE + Agent 的形态。 |
| Replit Agent | B | 云端 AI app builder | 从想法到 app，适合非专业开发者和快速原型。 | 和 v0/Lovable/Bolt 对比跟踪。`Skills` 进入官方文档后，它更值得被放在 `builder + skill layer` 的组合形态里看。 |
| Figma Make | A | AI app builder / design-to-prototype | 从 Figma frame 或自然语言生成交互、数据连接 app/prototype。 | 对前端和设计协作影响很大，尤其是设计到代码的边界；近期 `properties panel and annotations`、`local code for Figma Make`、`got skills` 这些信号一起说明，后续更值得观察的是 `local code` 接入与 `skills/context/annotations` 如何成为设计 agent 的协作层，而不是继续停留在“出原型更快”这个层面。今天可以把它更明确地看成 `design workspace`，而不只是 `AI app builder`。 |
| Layout.dev | B | AI app builder | 在 2026 AI app builder 比较中反复出现。 | 先观察。 |
| Magic Patterns | B | AI prototyping/design tool | 常被拿来和 v0、Lovable、Bolt 比较。 | 对 UI 原型有参考价值。 |
| Builder.io / Visual Copilot | B | Design-to-code / visual dev | 和前端落地、设计系统、代码生成相关。 | 适合纳入 Design System MCP 的参考。 |

| Claude Sonnet / Opus / Fable 系列 | A | Anthropic 模型线 | 对 Claude Code、长任务、agentic workflow 影响大。 | `Claude Sonnet 5` 说明 Anthropic 仍在把日常 agent 执行层做成稳定主线，不只是追逐旗舰叙事；`Claude Opus 5` 则把高能力上限继续往前推，但它真正重要的不是模型榜单位置，而是它如何被 `Claude Code`、`GitHub Copilot` 等工作流平台吸收。继续跟踪它是否真的提升长任务完成率、工具使用稳定性和成本结构。 |

| OpenRouter | B | AI Gateway / model router | 多模型路由、fallback、成本控制，和工程化 agent 关系密切。 | 已有相关原子知识，适合继续跟踪，并对比预算/权限/观测层是否继续补齐。 |
| Vercel AI SDK / AI Gateway | A | AI 应用基础设施 | 前端开发者构建 AI app、agent 和多模型工作流时最自然的 TypeScript 基础层之一。 | `AI SDK 7` 已把 `skills support`、`MCP Apps`、`terminal UI`、`reasoning control`、`runtime context` 拉进同一层；`The Agent Stack`、`Introducing the new Vercel Agent` 与 `AI Gateway` 的生产数据说明 Vercel 正在把 `路由 + workflow + 授权 + 交互 + dashboard` 收成完整 agent 基建。`2026-07-31` 的 `team / project budgets` 与 `2026-08-04` 的 `eve browser` 再补两条证据，说明它正在同时补 `治理层` 与 `浏览器执行层`。`2026-08-19` 的 `Vercel for Slack` 与 `2026-08-20` 的 `v0 authenticates to Snowflake without exposing the user's OAuth token` 又补了两条很强的新证据：Vercel 现在不只是在补 `agent runtime`，也在补 `team chat 入口` 与 `user-scoped connector security`，说明它的重点已经继续上移到 `agent entry + connector governance + safe auth proxy`。`2026-08-25` 的 `The end of credential sprawl for agents` 则把这条线再往前推了一步：`Vercel Connect` 已把 `short-lived scoped tokens + server-side minting / refresh + auth-field injection` 做成产品层，这说明连接器安全边界正在从“工程最佳实践”升级为 `secure connectivity layer`。 |
| Safari MCP Server | B | browser / MCP 工具 | 浏览器厂商原生把 Web 调试与自动化能力通过 MCP 暴露给 agent。 | 它和 `playwright-mcp`、`browser-use` 一起说明前端调试正在进入 `browser-native agent tooling` 阶段，值得作为长期样本跟踪。 |
| Firecrawl | B | Web data / crawling API / MCP 工具 | 把网页抓取、搜索、结构化抽取变成 Agent 可调用能力，适合 RAG、情报扫描和官方文档整理。 | 已有 [[../../../20-原子知识/产品项目/Firecrawl]]；优先观察是否值得接入每日情报扫描。 |
| OpenHuman | B | memory 工具 | 把 memory / workspace / context database 收成开源样本。 | 作为 `memory workspace` 方向继续观察。 |
| OmniRoute | B | 基础设施 / gateway | 多模型路由和控制面样本。 | 作为 `AI gateway / routing` 方向继续观察。 |
