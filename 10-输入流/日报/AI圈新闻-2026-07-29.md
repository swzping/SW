# AI圈新闻 - 2026-07-29

日期：2026-07-29

## 今日摘要

截至 `2026-07-29 10:00 CST` 的扫描，今天最值得保留的不是“又出了哪个新仓库”，而是四条继续收敛的工程主线：

1. `MCP` 已经从“工具连接协议”进入 `spec / host / SDK / auth` 的正式工程期。`2026-07-28 MCP Specification Release Candidate` 与 `GitHub MCP Server supports the next MCP specification` 一起说明，接下来更值得比较的是 `兼容性、任务扩展、授权治理、host / gateway 实现`，而不是 server 数量。
2. `coding agent 治理层` 继续加厚。`Custom Code Review rules for Codex`、`Agent automation controls in GitHub Issues`、`Claude Opus 5 in GitHub Copilot` 这一组官方信号继续说明，平台竞争点正在转向 `review policy、automation boundary、observability、handoff`。
3. `browser-native tooling` 仍在升温，但今天更应把它看成长期能力方向，而不是热仓库题材。`Safari MCP server`、`playwright-mcp`、`browser-use` 这条线持续说明，前端 agent 的真实分水岭会是页面观察、截图验证、console 检查和浏览器接管。
4. GitHub 热门仓库今天给出的新增样本，集中在 `skill / harness / memory / governance`。它们本身不都值得长期追踪，但共同支持了一个判断：Agent 工程层正在被拆成越来越明确的独立能力组件。

今天的来源覆盖：MCP 官方博客、OpenAI Developers / Help、GitHub Changelog / Trending、Anthropic News、Vercel Blog、Figma Blog、GitHub 仓库页。今天没有发现优先级高于上述四条主线的新旗舰模型或重大价格变动，因此日报继续聚焦 `协议 / 治理 / 浏览器 / 技能管理层`。

## 模型 / 论文 / API

- `MCP 2026-07-28 RC`
  - 今天最值得记住的不是单一 extension，而是它把 `stateless core`、`Tasks`、`Apps`、`auth hardening`、`deprecation policy` 收成同一版正式升级路线。

- `Claude Opus 5 + GitHub Copilot`
  - 更值得跟踪的是 `强模型如何被平台工作流吸收`，而不是单独追模型榜单名次。

- `Codex review rules`
  - 这是对你当前工作流最直接的一条 OpenAI 线索，因为它影响团队规范如何稳定注入 coding agent。

- 论文线说明
  - 今天没有发现比 `协议 / 治理 / 浏览器 / skill management` 更高优先级的新论文；论文覆盖更多仍服务于 `memory / context / observability` 的长期背景判断。

## 值得跟踪的问题

1. `MCP` 的下一阶段竞争点，会先落在 `host / SDK / gateway` 兼容，还是先落在 `enterprise auth / apps / browser-native workflow`？
2. `review policy + automation boundary` 会不会在 Codex、Copilot、Claude Code 三边收敛成默认工程层？
3. `Skill management layer` 会不会成为 `memory / context / workflow` 之外的新独立平台层？
4. `browser-native tooling` 会不会成为前端 agent 与通用 coding agent 的真正分水岭？
