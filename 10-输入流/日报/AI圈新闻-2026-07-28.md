# AI圈新闻 - 2026-07-28

日期：2026-07-28

## 今日摘要

截至 `2026-07-28 10:00 CST` 的扫描，今天最值得保留的不是单个新模型名，而是三条继续收敛的工程主线：

1. `MCP` 在官方 `2026-07-28` 规格发布候选中，已经明确进入 `stateless core + extensions + auth hardening + deprecation policy` 的工程期。这不是“又多了几个 server”，而是协议层真正变得更适合生产部署、网关路由和长任务执行。
2. `coding agent 治理层` 继续加厚。`Codex` 的 `Custom Code Review rules`、`GitHub Issues automation controls`、`GitHub MCP Server next spec` 这组信号，说明竞争点正在继续从“模型会不会写”转向“规则、边界、接管、兼容性”。
3. `技能 / 工作流 / 浏览器` 组合层仍在增强。OpenAI `skills` 官方文章、GitHub 上持续走热的 `skill` / `browser` / `memory` / `MCP` 项目，以及 `Playwright MCP`、`browser-use` 这类样本，继续说明对前端和 Agent 工作流更重要的是工程化组合，而不是单一热点仓库。

今天的来源覆盖：MCP 官方博客、OpenAI Developers、GitHub Changelog、Anthropic News、Vercel Blog、Figma Blog、GitHub Trending 与 GitHub Search API。今天没有发现比 `MCP RC` 更高优先级的 OpenAI / Google 新旗舰模型发布，因此日报继续聚焦 `协议 / 治理 / 浏览器 / skill` 四条主线。

## 热点新闻 Top 10

1. `The 2026-07-28 MCP Specification Release Candidate`
   - 来源：Model Context Protocol Blog，发布于 `2026-05-21`，最终版定于 `2026-07-28`。
   - 影响：这条是今天最重要的协议线索。重点不是“RC”三个字，而是它把 `stateless core`、`MCP Apps`、`Tasks extension`、`authorization hardening`、`deprecation policy` 一次性收进正式路线，直接影响未来 MCP host、gateway、SDK、browser tooling 的工程实现。

   - 来源：GitHub Changelog，`2026-07-25`。
   - 影响：这是 MCP 工程期的生态跟进证据。说明主流平台已经开始围绕新 spec 做兼容，而不是只停留在“列 server 清单”。

   - 来源：GitHub Changelog，`2026-07-24`。
   - 影响：Agent 自动执行边界正在被显式产品化。以后比较 coding agent，不能只看它能自动做多少，还要看它怎么被限制、接管和审计。

   - 来源：GitHub Changelog，`2026-07-25`。

## 模型 / 论文 / API

- `MCP 2026-07-28 RC`
  - 今天最值得记住的是它把 `stateless protocol core`、`Tasks extension`、`MCP Apps`、`authorization hardening`、`formal deprecation policy` 做成同一版升级。这会直接影响 MCP host、gateway、browser tooling 和企业接入的工程实现。

- `Claude Opus 5`
  - 更值得跟踪的是它如何被 `GitHub Copilot`、`Claude Code` 等平台吸收，而不是单独追模型榜单。

- `Codex review rules`
  - 这是今天对你最有直接工作流价值的一条 OpenAI 线索，因为它影响团队规范如何稳定注入 coding agent。

## 值得跟踪的问题

1. `MCP` 的下一阶段竞争点，会先落在 `spec / host / SDK` 兼容，还是先落在 `enterprise auth / apps / browser-native tooling`？
2. `review policy as code` 会不会在 Codex、Copilot、Claude Code 三边收敛成默认工程层？
3. `browser-native tooling` 会不会成为前端 agent 与通用 coding agent 的真正分水岭？
4. `skill / memory / gateway / harness` 这四层里，哪一层最值得优先转成你自己的 MCP / 工作台能力？
