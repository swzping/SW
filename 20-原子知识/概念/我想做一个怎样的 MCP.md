# 我想做一个怎样的 MCP

标签：#mcp #agent #rag #概念 #问题

## 核心内容

我想做的 MCP 不应该只是“把工具接进来”，而应该解决一个真实、高频、能被标准化的问题。当前最自然的方向，是让个人知识库、工作台、输入流和主题地图变成 Agent 可以安全调用的能力。

## 我的判断

一个值得做的 MCP，应该优先服务“个人知识库整理和推进”，而不是一开始就追求通用工具市场。它的价值在于让 Agent 能读取工作台、识别待拆解想法、生成整理建议、创建原子知识、更新主题地图，并保留人工确认边界。

最近更明确的一条优先级判断是：第一版应该先把“整理资料”做稳，再逐步补“推进想法”。原因不是后者不重要，而是资料整理更容易定义输入输出、确认写入边界和验证结果，也更适合先验证 MCP 的受控读写能力。

对当前知识库来说，“整理资料”至少包括读取工作台、读取整理建议、创建原子知识、把输入流候选收束成可确认草稿；“推进想法”则会更快触碰到决策、优先级、主题地图更新和长期记忆写回。这意味着两者不是二选一，而是应按顺序推进：先让 MCP 稳定完成整理闭环，再让它参与更高层的问题推进与下一步建议。
