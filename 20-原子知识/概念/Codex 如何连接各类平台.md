# Codex 如何连接各类平台

标签：#codex #agent #mcp #computer-use #browser #概念

## 核心内容

Codex 连接外部平台，不应只理解成“能不能接一个网站”，而应先区分接入层。对我当前工作流，至少有四种典型方式：`MCP` 用于标准化接工具和数据源，`API` 用于调用明确服务能力，`browser / MCP` 用于页面级调试与浏览器自动化，`Computer Use` 用于处理没有稳定 API 或 MCP 接口的桌面与网页登录场景。

## 我的判断

判断 Codex 能否连接某个平台，关键不在“有没有技巧”，而在“这个平台适合哪一层接入”。优先级应该是：先看是否有官方 API 或官方文档，再看是否适合做 MCP server，其次才是浏览器自动化或 Computer Use。这样才能把平台接入变成可维护工作流，而不是一次性演示。

对抖音这类平台，短期更现实的方案通常不是直接写成知识库 MCP，而是分层处理：公开资料抓取走网页/搜索层，登录后页面观察走浏览器或 Computer Use，真正需要长期复用的结构化能力再考虑 MCP 化。敏感账号、验证码、私有数据和高权限动作不应默认自动化。

## 接入方式分层

- `MCP`：适合把知识库、内部工具、浏览器调试能力、文档系统封装成稳定工具层。
- `API`：适合能力边界清晰、权限模型明确、返回结构稳定的平台。
- `browser / MCP`：适合页面观察、前端调试、表单操作、流程回放。
- `Computer Use`：适合没有稳定接口、需要人工登录或桌面交互的软件，但自动化边界要更保守。
